# ADR 0022 — The user guide is self-contained Starlight source, not repo-linked documentation

**Status:** Accepted
**Date:** 2026-07-30

## Context

`docs/guide/` holds the task-oriented documentation for installing, configuring
and running Argus. It was written to be read **on GitHub**, and it shows: 18
relative links pointed out of the folder — 15 into `docs/adr/`, one to
`CONTEXT.md`, one to `docs/design/authz-skill-design.md`, one to the
`Dockerfile` — plus prose references to ADR numbers and to `pkg/` source paths.
One of those was a `cp pkg/skill/builtin/...` command that only works for
somebody who has cloned the repository, which a user who installed the binary
has not.

That shape is the natural consequence of writing docs inside a repo where the
ADRs are good and one `../` away. It is also the wrong shape for the audience:
these pages are for operators who host Argus and developers who receive its
reviews. Neither has the repo checked out, and neither should be handed an
architecture decision record as the explanation for why their deploy needs one
replica.

The guide is to be published on a **Starlight** documentation site that lives in
a **separate repository**. That site does not exist yet, so the folder must be
importable without instructions attached — and we cannot build it from here to
check our work. The conventions this ADR relies on were therefore researched
against Starlight 0.41.5 / Astro 7.1.6 and recorded, with sources, in
[`docs/research/starlight-content-conventions.md`](../research/starlight-content-conventions.md).

Two readers now want incompatible things from the same files. Starlight wants
`index.md`, mandatory frontmatter, absolute site paths and `:::` asides; GitHub
wants `README.md`, relative `.md` links and blockquotes. Astro does not rewrite
relative Markdown links, so there is no form that satisfies both.

## Decision

**`docs/guide/` is content source for the Starlight site. Where the two readers
conflict, Starlight wins.**

Concretely:

- **No relative link may leave the folder.** Those files are not imported, so
  such a link is broken on the site by construction. Absolute URLs stay legal:
  to third-party projects (`cert-manager.io`, `external-secrets.io`, …) and to
  the Argus repository only for things a user actually uses — releases, issues,
  the security policy. Never to source code, never to an ADR, never to a design
  document.
- **The *why* is absorbed into prose, in the reader's language, or cut.** Where
  a sentence stood on its own the citation simply goes; where the link carried
  the explanation it is rewritten as user-facing prose; where the rationale
  serves no user — the authz skill's design write-up — it is cut.
- **Every page carries `title`, `description` and `sidebar.order`.** Ordering is
  all-or-nothing: a page without `order` sorts to `Number.MAX_VALUE` and sinks
  below every ordered page, so all eight declare one. Body `<h1>`s are removed,
  since Starlight renders the heading from `title`.
- **`README.md` became `index.md`**, the section landing page.
- **Blockquote callouts became typed asides** — `caution` for security and
  spend, `tip` for recommendations, `note` for version and migration notes.
- **Domain vocabulary is glossed inline at first use per page**, because
  `CONTEXT.md` is no longer reachable from here.

**Two requirements fall on the site repository.** Both are load-bearing, and
neither can be satisfied from this repo:

1. **Mount the folder at `src/content/docs/guide/`**, so pages resolve under
   `/guide/…`. Starlight's `docsLoader()` hard-codes its `base` to
   `<srcDir>/content/docs` and does not expose it, so the folder must physically
   appear there — by submodule or by sync. Mounted anywhere else, every internal
   link in the guide breaks silently.
2. **Relabel the sidebar groups in `astro.config.mjs`.** An autogenerated group
   takes the directory name verbatim, so `channels/` and `deployment/` render
   lowercase. No `_meta.json`, no frontmatter override, no per-directory config
   exists to fix that from the content side.

## Consequences

- **`docs/guide/` no longer reads well on GitHub**, and that is accepted rather
  than regretted: internal links point at site slugs, `:::caution` shows as
  literal text, and the folder has no landing page because GitHub does not
  render `index.md`. The public reads the site; the folder is its source.
- **Some rationale now exists twice** — once in an ADR, once as prose in a
  guide — and the two can drift. This is the price of a guide that explains
  itself. When an ADR changes a user-visible *why*, the guide must be revisited;
  nothing enforces that but the section in `AGENTS.md`.
- **Renaming a page or a directory now breaks public URLs.** Before, a rename
  cost a relative link; now it costs a link somebody else published.
- **The internal links assume the site is served from the domain root.** They
  are root-absolute paths written by hand, and Astro does not inject its `base`
  into those. If the site is ever deployed under a sub-path, every `/guide/…`
  link in the guide breaks — a third requirement on the site repo, and the one
  most likely to be discovered late.
- **Nothing verifies the rule.** A CI check would be a grep, and was deliberately
  left out of this change to keep it scoped to documentation. Until it exists,
  the rule holds only because `AGENTS.md` states it — and the 18 links this ADR
  removes are evidence of how quickly it erodes without one.
- **The guide can no longer answer "why is it built this way?" by pointing.** It
  either answers in its own words or does not raise the question. That is a
  discipline on the writing, and it is the point.

## Alternatives considered

- **Keep relative links and have the site rewrite them** with a plugin such as
  `rehype-relative-markdown-links`. Rejected: it buys GitHub readability at the
  cost of a dependency in a repository we do not control and cannot test from
  here, and it would still not fix `README.md` versus `index.md`, nor the
  blockquote-versus-aside split. It converts a clean constraint into a build
  that must keep working.
- **A "Why Argus works this way" page inside the guide**, gathering the
  user-relevant decisions so the pages could link internally. Rejected as the
  default: it concentrates the duplication in one file, but that file is an ADR
  index in disguise — the exact contamination being removed — and it drifts from
  21 ADRs instead of from the handful of sentences that actually reach a user.
- **Let GitHub win and have the site transform the files on import.** Rejected:
  it defers the whole problem to a repository that does not exist yet, and makes
  the guide's correctness depend on a transformation nobody has written.
- **Drop internal links entirely** and use plain textual references, making the
  folder immune to where it is mounted. Rejected: the guide's 18 *internal*
  cross-references — a different set from the 18 outbound links above, which
  merely happens to be the same size — carry the main reading path (getting
  started → configuration → providers), and killing them to avoid committing to
  a URL prefix is a bad trade.
